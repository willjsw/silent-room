# MR 작성 양식 (AI 참고용)

MR 생성 지시를 받으면 `.ai/templates/mr.md` 의 항목을 **전부** 채운다.
항목을 삭제하지 않고, 해당 없는 항목은 "해당 없음"으로 적는다.

## 작성 규칙

- 제목: 대표 커밋 제목과 동일 형식 — 하네스 설정이 정한 커밋 제목 형식을 따른다
- 대상은 통합 브랜치
- 본문 한국어, 개조식, 명사형 종결
- 도구 생성 표기·`Co-Authored-By` 넣지 않음
- "변경 사항"은 커밋 로그를 요약하되 파일 나열이 아닌 행위 단위로
- "영향 범위"에는 바뀐 모듈·패키지 경로와 영향 받는 외부 계약을 명시
- "테스트 수행 내역"은 실제 실행한 것만 체크. 실행하지 않은 항목은 체크하지 않고 사유를 적음
- "의존성 규칙 위반 여부"는 `script/run-lint-test.sh` 통과로 판단한다 (스크립트가 grep 검사를 포함).
  스크립트가 잡지 못하는 모듈 간 직접 호출은 눈으로 확인한다

## Assignee·Reviewer

**별도 지시가 없으면 둘 다 하네스 설정 `mr.default_assignee` 가 정한 사람으로 지정한다.**
지정하지 않으면 MR 이 아무에게도 할당되지 않은 채 열려 누가 볼 차례인지 알 수 없다.

다른 담당자를 지정하라는 지시가 있으면 그것을 따른다.

## 생성 수단

`.ai/forge.md` 의 **MR 생성** 명령을 쓴다. 제목·본문·대상 브랜치·Assignee·Reviewer 를 모두
넘긴다. **본문 자동 채움 기능에 맡기지 않는다** — 템플릿 항목이 누락된다.

## 검토한 대안 (해당할 때만 더한다)

결정 게이트에서 **기각된 선택지가 있을 때만** 이 절을 템플릿 뒤에 더한다. 없으면 넣지 않는다.

```markdown
## 검토한 대안

| 선택지 | 기각 근거 | 되돌리기 비용 |
|---|---|---|
| <기각된 안> | <왜 택하지 않았는가> | <바꾸려면 무엇을 고쳐야 하는가> |
```

**표는 ADR 유무와 무관하게 채운다.** MR 만 보는 사람이 기각 근거를 따라갈 수 있어야 한다.
ADR 을 쓰는 결정이면 표 아래에 그 번호를 한 줄로 덧붙인다 — 더 긴 맥락은 `.ai/adr.md` 가 정한
대안 절에 있다. ADR 을 쓰지 않는 결정이면 **이 절이 대안의 유일한 기록**이다
(`.ai/AI_AGENT.md` 의 "금지 사항").
