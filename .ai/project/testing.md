### 무엇을 어느 수준으로 검증하나

| 수준 | 대상 | 도구 |
|---|---|---|
| 단위 | `domain` 의 규칙, `application` 의 유스케이스 | JUnit 5. 스프링 컨텍스트를 띄우지 않는다 |
| 통합 | WebSocket 연결·구독·브로드캐스트 경로 | `@SpringBootTest` + 임의 포트 |

`domain` 은 프레임워크에 의존하지 않으므로 단위 테스트에 모킹이 필요 없다.
**모킹이 필요해지면 그것은 계층이 잘못 놓였다는 신호다.**

### 외부 의존을 어떻게 다루나

외부 시스템이 없다. 방 상태는 인스턴스 로컬 메모리라 테스트가 실제 인프라에 붙지 않는다.
영속 저장소나 Redis 가 들어오면 Testcontainers 로 실물을 띄운다 — 인메모리 대체물은
실제 동작과 갈라져 통과하는 테스트를 만든다.

### 하지 않는 것

- `Thread.sleep` 으로 비동기를 기다리는 것. WebSocket 테스트는 `CountDownLatch` 에 타임아웃을 건다
- 실제 시각(`LocalDateTime.now()`)에 의존하는 단정. 시각이 필요하면 `Clock` 을 주입한다
- 판정을 통과시키기 위한 assertion 삭제나 테스트 약화
