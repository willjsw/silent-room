# retro — 사용 기록에서 마찰 신호를 집계해 하네스 보완점을 뽑는다

수집 → 집계 → 신호 해석 → 보완 제안. **제안까지이고 반영은 사람 승인 뒤다.**
하네스 중립 절차 정본. 어떻게 호출하는지는 각 하네스 어댑터가 정한다.

지금 무엇이 마찰인지는 사람이 대화를 되짚어야 알 수 있고, 그래서 같은 문제가 반복돼도 드러나지
않는다. 이 절차는 **기록이 세고 사람이 판단하는** 경계를 고정한다.

## 입력

- 기간. 기본은 최근 4주 (`--since YYYY-MM-DD`)
- 사용 기록 위치. 하네스 설정 `usage.log_path` 가 정하는 위치. 같은 설정의 환경 변수가 덮는다
- 세션 기록(있으면). **사용자가 넘긴 파일·폴더만 읽는다.** 다른 사람의 홈 디렉터리를 뒤지지 않는다

## 1. 수집 — 무엇이 기록되는가

`script/usage-log.sh` 가 남긴다. **명령 내용·문서 본문·사람 이름은 남지 않는다** — `script/usage-vocab.sh`
에 적힌 허용 라벨과 허용 키의 `키=값` 만 통과하고 나머지는 버려진다. 모르는 출처는 `other` 가 된다.
집계(`script/usage-report.sh`)도 같은 목록으로 입력을 다시 검증하므로, 다른 곳에서 만들어진
로그에 이름·명령이 섞여 있어도 보고서에 나오지 않는다(제외 건수만 `DROPPED` 로 표기).

| 종류 | 남기는 쪽 | 상세 |
|---|---|---|
| `block` | `githooks/commit-msg`·`pre-commit`·`pre-push` | 어느 가드가 무엇으로 막았는가 |
| `preflight` | `work-preflight.sh` | 판정 결과 (`plan`·`standalone`·`open-mr`·`spec-missing`·`fetch-failed`·`mr-query-failed`) |
| `review` | `review-mr.sh` | `mr=N round=N exit=N` — 어느 경로로 끝나든 남는다 |
| `command` | 커맨드 호출 경로 | 아직 어느 자산도 남기지 않는다 — 집계가 **미수집**으로 표기한다 |

## 2. 집계 — 숫자는 스크립트만 센다

```bash
script/usage-report.sh [--since YYYY-MM-DD] [로그파일|디렉터리 ...]
```

**모델이 따로 세거나 추정하지 않는다.** 리포트의 숫자는 이 출력(표와 `KEY=VALUE`)만 쓴다.
기록이 없으면 오류가 아니라 **미수집**이다 — 수집 경로가 아직 돌지 않은 것과 마찰이 없는 것은
구별할 수 없으므로 0 으로 세지 않는다.

**미수집(`COLLECTED=no`)과 기간 내 0건(`PERIOD_EMPTY=yes`)은 다르다.** 유효한 기록이 기간 밖에만
있으면 수집 경로는 돌고 있고 그 기간에 이벤트가 없었을 뿐이다. 이것을 미수집으로 적으면 수집이
안 된다는 잘못된 신호가 된다 — 기간을 넓혀(`--since`) 다시 보거나 "이 기간에 이벤트 없음"으로 적는다.

리뷰 회차 상한 값은 이 절차도 집계 스크립트도 갖지 않는다. 리뷰 스크립트가 갖는 주 상한 하나다.

## 3. 신호 → 원인 → 보완 대상

신호마다 **증거(어느 기록에서 몇 건)** → **원인 가설** → **보완 대상(파일)** 을 붙인다.
증거 없는 추정은 "가설"로 표시한다.

| 신호 | 집계 항목 | 뜻 | 보완 대상 |
|---|---|---|---|
| 리뷰 회차 상한 도달 | `MRL_CAP_HITS` | 루프가 수렴하지 않는다 | `.ai/templates/code-reviewer.md` 점검 항목·반증 절차, `review-mr.sh` 가 갖는 주 상한 |
| 한 파일 반복으로 중단 | `REPEAT_STOPS` | 코드가 아니라 명세가 틀렸을 후보 | 해당 이슈의 `docs/spec/`, `.ai/templates/developer.md` 재시도 절 |
| 같은 가드가 반복해 차단 | `REPEAT_BLOCK_GUARDS` | 훅 오탐 후보 | 해당 `script/githooks/*` 패턴, `script/test-review-loop.sh`·`test-usage-log.sh` 케이스 |
| 착수 불가·실행 실패 판정 집중 | 착수 판정 표 | 구현 절차 착수 전 상태가 자주 어긋난다 | `.ai/workflows/work.md` 중단 조건, `work-preflight.sh` 검사 순서 |
| 커맨드 직후 교정 발언 집중 | 세션 기록 (수동) | 절차·출력이 기대와 다르다 | 해당 `.ai/workflows/` 절차 |
| 커맨드 없이 forge 쓰기·push 실행 | 세션 기록 (수동) | 절차 우회 — 무겁거나 트리거가 안 걸린다 | 어댑터 트리거·적용 범위 |

마지막 두 행은 **세션 기록이 필요하고 집계 스크립트가 덮지 않는다.** 기록을 넘겨받지 못했으면
집계하지 않고 "미수집"으로 남긴다 — 세지 않은 것을 없는 것으로 적지 않는다.

## 4. 보고

턴의 마지막 메시지로 낸다. 절: **기간·입력 / 지표(집계 출력 그대로) / 발견(신호·증거·가설) /
보완 제안(우선순위·대상 파일·변경 요지·기대 효과·검증 방법) / 미수집·한계**.

- 이름·계정·이메일·명령 원문·코드 조각을 넣지 않는다. 집계와 마스킹된 짧은 인용만
- 어느 제안을 반영할지 **사용자가 고른다.** 승인 없이 정본을 고치지 않는다
- 하네스에서 덜어내는 것도 보완이다 — 추가만 하지 않는다
- 반영할 때는 변경마다 검증 수단(테스트 케이스)을 함께 붙인다. 검증 방법이 없는 제안은 "가설"로 남긴다

## 하지 않는 것

- 개인 식별 정보·명령 내용 기록
- 사용자가 넘기지 않은 세션 기록 열람
- 회고 결과의 자동 반영
- 기록이 없는 항목을 0 으로 적는 것 (미수집과 0 은 다르다)
