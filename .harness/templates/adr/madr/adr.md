# 결정 기록 (ADR)

되돌리기 비싼 결정의 **"왜" 를 남기는 로그**다. 이 프로젝트는 **MADR** 방식을 쓴다.

**이 파일은 harness.toml 에서 생성된다. 직접 고치지 않는다** — `[adr]` 를 바꾸고
`harness render` 를 돌리면 스타일에 맞는 사전이 다시 만들어진다.

역할 계약과 절차는 이 파일만 참조한다. 명령도 상태 문자열도 절 이름도 거기 적지 않는다.

| 항목 | 값 |

| 대안을 적는 절 | `## Considered Options` 와 `## Decision Outcome` |

## 불변식

스타일과 도구가 바뀌어도 이 넷은 그대로다.

1. **초안은 사람이 승인한 결정에만 만든다.** "결정이 났으니 기록해 두자" 는 이유로 만들지 않는다.
2. **어느 역할도 상태 필드를 바꾸지 않는다.** 문서 정리자는 대체가 필요하다는 사실만 보고한다.
3. **효력은 상태 문자열이 아니라 통합 브랜치 머지에서 생긴다.** 열린 리뷰 요청 안의 결정 기록은
   아직 확정이 아니라 리뷰 대상이다. 어느 에이전트도 머지하지 못한다.
4. **번호를 재사용하지 않는다.** 이미 머지된 기록이 옛 번호를 가리키고 있어, 번호를 당겨 메우면
   그 참조가 다른 결정을 가리키게 된다. 문서를 지울 때는 최대 번호 자리에 표식을 남긴다.

## 언제 쓰는가

되돌리는 비용이 큰 결정에만 쓴다. **애매하면 쓰지 않는다** — 기록이 많아지면 아무도 읽지 않는다.

| 쓴다 | 쓰지 않는다 |
|---|---|
| 외부 계약·프로토콜·데이터 포맷 | 클래스 이름, 메서드 분리 |
| 저장 구조 | 변수명·포맷 |
| 외부 의존 도입·제거 | 라이브러리 패치 버전 올림 |
| 계층 경계 변경, 책임을 어느 모듈에 둘지 | 명세 범위 안의 구현 선택 |
| 검토한 대안이 있고 나중에 "왜 이렇게 했지" 가 나올 것 | 대안이 없었던 결정 |
| 이 리포 고유의 판단 기준 (`.ai/project/architecture.md` 참조) | **작업 절차·워크플로 조정** |

**절차와 워크플로는 대상이 아니다.** 되돌리는 비용이 문서 몇 개와 스크립트 하나여서 문턱에
닿지 않고, 절차는 돌려보며 고치는 것이라 기록으로 만들면 같은 주제가 며칠 만에 연쇄 대체된다.
절차를 왜 그 형태로 정했는지는 이슈와 리뷰 요청 본문에 남는다.

## 무엇이 결정 기록이 아닌가

| 아닌 것 | 어디로 |
|---|---|
| 검증 없이 쓴 추측을 나중에 바로잡은 기록 | 정정한 내용만 현재형 문서에 |
| 도구 동작·경로·버전처럼 관측으로 확인되는 사실 | 현재형 문서(`.ai/AI_AGENT.md`, `.ai/project/`) |
| 작업 수행 이력 (리뷰 몇 회, 무엇을 고쳤는지) | 리뷰 요청과 git 이력에 이미 있다 |

**결정이 실제로 바뀌었을 때만** 새 기록을 쓰고 기존 것을 대체 표기한다.
사람이 한 번도 판단한 적 없는 내용을 기록으로 만들지 않는다.
