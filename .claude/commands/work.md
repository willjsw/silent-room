> **명시 호출 전용.** 코드·이슈·리뷰 요청을 만드는 작업이므로 사용자가 직접 부른 턴에서만 돈다.

**절차 정본은 `.ai/workflows/work.md` 다. 먼저 읽고 그대로 따른다.**
이 파일에 절차를 복사하지 않는다 — 복사본은 정본 개정을 따라가지 못한다.

대상 이슈: **$1**

경로는 정본이 정한다 — 분해가 있으면 요구사항 경로, 없으면 단독 task 경로다.
**판정은 로컬이 아니라 원격의 통합 브랜치 기준이다.**

`$1` 이 비어 있으면 아무것도 하지 말고 이슈 번호를 요구한다.

## 이 하네스에서의 위임

| 정본의 표현 | 이 하네스에서 | 넘기는 것 |
|---|---|---|
| 착수 판정 (착수 전 · 위임 직전) | `script/work-preflight.sh <이슈번호>` — Bash | 이슈 번호 |
| task 이슈 동기화 (분해가 있을 때만) | `script/sync-task-issues.sh <이슈번호>` — Bash | 이슈 번호 |
| 구현자 역할 | `developer` 서브에이전트 | 1회차: 이슈 번호 (+ 분해가 있으면 task↔이슈 매핑) / 재시도·마무리: 같은 것 + **리뷰 요청 번호** + 리뷰 본문 전체 |
| 리뷰 | `script/review-mr.sh <번호>` — Bash | 리뷰 요청 번호 |

**이 루프의 리뷰 수단은 `script/review-mr.sh` 하나다.** 어느 도구로 리뷰할지는 하네스 설정의
`roles.code-reviewer` 가 정한다 — 구현한 모델이 자기 코드를 리뷰하지 않게 하려는 배치다.
**`code-reviewer` 서브에이전트를 이 루프의 리뷰 수단으로 쓰지 않는다.** 회차 라벨을 올리고
상한에서 멈추는 것은 그 스크립트뿐이라, 그 경로를 건너뛴 리뷰는 상한 없이 반복된다.
그 서브에이전트는 **이 커맨드 밖에서 사용자가 직접 부를 때만** 쓴다.

## 루프 운영 — 이 하네스의 결합만

**순서·분기·상한은 정본과 스크립트가 갖는다.** 여기 적는 것은 무엇을 어느 도구로 부르는가뿐이다.

- **루프를 도는 주체는 이 세션이다.** 서브에이전트끼리 서로를 부르지 않는다.
- 위임표의 스크립트는 Bash 로 실행한다. 호출 시점과 인자는 정본이 정한다.
- 스크립트가 낸 사유는 **그대로** 보고한다. 요약하거나 다시 쓰지 않는다.
- `script/review-mr.sh` 는 diff 조회·리뷰·등록을 모두 하므로 **diff 를 이 세션이 중계하지 않는다.**
  리뷰 도구 호출은 수 분 걸릴 수 있다 — Bash 타임아웃을 넉넉히 준다.
- **분기는 스크립트 종료 코드로만 한다.** 출력의 인상으로 판단하지 않는다.
- **세션은 회차 라벨을 손대지 않고, 회차도 반복 지적도 세지 않는다.** 스크립트가 센다.
- 재시도와 마무리 모두 `developer` 에게 **리뷰 요청 번호**와 리뷰 본문을 그대로 넘긴다.
  번호 없이는 답글도 노트도 달 곳을 확정할 수 없다.
- 매 회차 진행 상황을 한 줄로 알린다. 조용히 돌지 않는다.
